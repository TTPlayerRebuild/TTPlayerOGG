# OGG 提交接口和 64 位文件位置修正

日期：2026-10-19。

## 实现

- 最后释放 Reader 保存的原 ABI 保留；新增可选 MetadataCommit（IID `3AB643C1-D8A4-4D49-9CBB-EF196B04B6E7`），显式提交后重复调用返回同一结果，析构不再次写盘。写入前关闭解码状态，之后不允许继续修改或读取。
- 对旧宿主不支持 `IStream::Commit` 的两个返回值 `E_NOTIMPL`/`STG_E_INVALIDFUNCTION` 兼容放行；真实写盘、刷新、短写错误仍回滚并返回错误。
- Windows 的 long 只有 32 位。原 Vorbisfile tell 回调导致超过 2 GiB 的位置截断，现将私有静态库的回调及适配层统一扩为 64 位；stdio 回调改为 `_ftelli64`。变更在构建目录应用，不修改下载缓存或宿主 ABI，详见 [来源记录](../third_party/ORIGIN.md)。
- 依赖仍为 libogg 1.3.6、libvorbis 1.3.7、Opus 1.6.1、opusfile 0.12；2026-10-19 官方核查没有更新的稳定版本。

## 验证结果

- 既有 Vorbis 67 项、Opus/封面 94 项回归通过。
- 5 组保存测试覆盖正常提交、两个未实现返回值及两个真实错误；校验重新打开的标签、音频包 SHA-256、重复调用及析构不重试。
- 将正常 Ogg 头页与 EOS 页分别放在 `2^31+123`、`2^32+123` 的稀疏文件中：旧 DLL 打开失败，新 DLL 打开及读取注释成功。这验证 64 位位置回调，**不代表全部超大文件定位情况通过**；两页间存在数 GiB 全零空洞时，上游扫描仍会很慢，此非正常媒体样本的中点定位未通过限时测试。
- XP SP3 与 Win7 SP1 各运行 AAC/OGG/APE 联合 103 项，均无失败；82 个 PCM/写回文件/封面输出 SHA-256 与 Windows 11 一致。包含 Vorbis/Opus 解码、8 声道、链式流、不可定位流、小缓冲、保存与封面。
- Windows 11 原版 5.7.9 与重建版实际加载本 DLL 并播放 Opus，无错误对话框，正常关闭；旧系统宿主测试另见综合报告。

DLL：340480 字节，SHA-256 `7b0242371f265bdac78d094495c3190c13c939033b649d9bc2f37220686dca69`；XP/Win7 静态导入审查通过（4 个系统 DLL、100 个导入）。

测试和样本只放在 `rebuild/tests/audio_plugins_fix_20261019`，不进入仓库、Action 或发行 ZIP。没有修改工作区原 AddIn 或用户音频。链间声道/采样率变化仍明确拒绝；本轮不声称所有原版异常路径或 GUI 操作完全一致。
